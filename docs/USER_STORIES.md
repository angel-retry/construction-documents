# 需求規格與使用者故事 (User Stories & PRD)

## 一、 需求背景與核心目標

在工程施工文件系統的「施工路段（`/sites`）」管理中，各路段均需設定其「實際施工日期（`work_dates`）」。該欄位為後續產出公共工程每日施工日誌與結算驗收之關鍵依據。

目前系統僅提供純文字框，要求使用者自行手動輸入如 `115/9/5、115/9/10~115/9/12` 之格式字串，存在以下問題：
1. **輸入門檻高**：工程人員需手動核對日曆，逐一鍵入民國年與頓號。
2. **容易打錯格式**：遺漏頓號或輸入無效日期常導致後端驗證失敗（`validateWorkDates` 報錯）。

**本次改造核心目標**：在保留手動輸入彈性的前提下，導入 **月曆多選功能**，並由系統自動將勾選之連續與離散日期轉換為標準工程區間字串。

---

## 二、 使用者角色 (Persona)

* **現場工程人員 / 行政人員**：負責將現場實際施工記錄登打進系統，需要直觀、快速勾選日期，避免繁瑣鍵盤輸入。
* **工務主管 / 稽核人員**：依賴系統產出合規、連續性正確之施工日誌。

---

## 三、 使用者故事 (User Stories)

### US-1：月曆多選互動
* **身分**：作為現場工程人員
* **需求**：在路段設定頁面中，我希望能點擊按鈕開啟當月月曆並直接勾選多個施工日期。
* **價值**：無需切換至外部日曆軟體對照，直觀點選即可完成登記。

### US-2：連續日期自動合併為區間
* **身分**：作為現場工程人員
* **需求**：當我勾選離散與連續天數（例如 5, 10, 11, 12, 27, 28, 29 日）時，系統能自動在輸入框填入 `115/9/5、115/9/10~115/9/12、115/9/27~115/9/29`。
* **價值**：免去手動計算哪些天是連續的負擔，自動產出規範字串。

### US-3：施工日期唯讀化與點擊觸發 (v1.1 調整)
* **身分**：作為系統管理者與使用者
* **需求**：施工日期文字框設為唯讀（readOnly），禁止手動任意打字；使用者可點擊輸入框或日曆按鈕開啟月曆進行勾選。
* **價值**：徹底防堵人工手誤鍵入非標準格式字串，強制所有日期皆由演算法產出合規格式。

### US-4：後端驗收完全相容
* **身分**：作為系統開發人員
* **需求**：月曆產出之字串必須 100% 通過現有後端 `validateWorkDates` 檢核，並順利送交 Python 報表引擎。
* **價值**：零破壞性更新，不影響既有標案資料與後續 Excel 匯出。

## 四、 驗收準則 (Acceptance Criteria)

| 測試案例 | 輸入勾選天數 | 預期輸出字串 (以 115 年 9 月為例) | 備註 |
| :--- | :--- | :--- | :--- |
| **AC-1 空白日** | 未選取任何日期 | 空字串 `""` | 清除功能 |
| **AC-2 單一日** | 僅選 `[5]` | `115/9/5` | 單日不帶波浪符 |
| **AC-3 單一連續區間** | 選 `[10, 11, 12]` | `115/9/10~115/9/12` | 連續天數自動合併為區間 |
| **AC-4 混合型多區間** | 選 `[5, 10, 11, 12, 27, 28, 29]` | `115/9/5、115/9/10~115/9/12、115/9/27~115/9/29` | 離散與連續混和，以頓號 `、` 分隔 |
| **AC-5 兩天連續** | 選 `[1, 2]` | `115/9/1~115/9/2` | 連續 2 天即應合併為區間 |
| **AC-6 反向解析** | 既有欄位為 `115/9/10~115/9/12` | 打開月曆 10, 11, 12 號應為勾選狀態 | 支援原有資料修改 |
| **AC-7 輸入框唯讀** | 於輸入框鍵盤打字 | 欄位無法編輯，游標為手勢箭頭，點擊展開月曆 | 強制月曆操作 |

## 五、 需求修訂歷程 (Change Log)

* **2026-10-22 (v1.1)**：依使用者回饋，將施工日期文字框由「允許手動輸入」調整為「強制唯讀（readOnly）」，杜絕手動輸入錯誤，並強化點擊輸入框直接開啟月曆之互動體驗。
* **2026-10-22 (v1.0)**：初版規格建立，定義月曆多選與連續天數合併演算法。
