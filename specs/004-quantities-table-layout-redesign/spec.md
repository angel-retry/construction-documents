# Feature Specification: 數量看板專業報表排版重構 (Quantities Table Layout Redesign)

**Feature Branch**: `004-quantities-table-layout-redesign`  
**Created**: 2026-11-04  
**Status**: Draft  
**Input**: 依據 `preview-table.html` 視覺原型，將 `/quantities` 頁面路段工項表格改造為「現代化專業工程報表風」：具備邊框底色之表頭骨架、數值靠右等寬排列（tabular-nums）、金額重點高亮、資料列懸停高亮、精緻移除按鈕與分配狀態色彩。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 現代化專業表頭骨架與數值靠右對齊 (Priority: P1)

作為工程核銷人員，在「每日數量與帳務總覽」（`/quantities`）頁面檢視路段工項清單時，我希望表頭具備清晰的底色與分欄骨架，且「本月數量」、「單價」、「本月金額」等數值欄位嚴格靠右對齊並以等寬數字（tabular-nums）呈現，避免因文字數值齊頭靠左導致欄位歪斜與閱讀審核疲勞。

**Why this priority**: 這是工程報表最基本且關鍵的易讀性標準。數值靠右與等寬字體能讓千分位與小數點垂直對齊，大幅提升審核金額與數量的效率與專業度。

**Independent Test**:
進入特定標案之 `/quantities` 展開任一路段，檢視表頭與工項列：確認表頭具備淺灰底色（`#f1f5f9`）與清晰邊框；確認所有工項的「本月數量」、「單價」、「本月金額」數值均嚴格靠右排列，小數點垂直對齊。

**Acceptance Scenarios**:
1. **Given** 使用者進入數量看板並展開路段，  
   **When** 頁面呈現工項列表時，  
   **Then** 表頭（`quantity-column-head`）呈現統一的淺灰底色與圓角邊框，且數值標題與左側資料欄位 100% 垂直對齊。
2. **Given** 工項列呈現「本月數量」、「單價」與「本月金額」，  
   **When** 使用者查看或輸入數值時，  
   **Then** 數值統一靠右排列（`text-align: right`），採用等寬數字字型，且本月金額呈現深藍色高亮標註。

---

### User Story 2 - 資料列邊界層次、懸停高亮與微型移除按鈕 (Priority: P2)

作為填報人員，在包含數十個工項與天數的龐大網格中填寫數量時，我希望資料列具備柔和的分隔線、滑鼠懸停（Hover）淡雅高亮底色與優雅的微型移除按鈕，避免在水平滾動時看錯行，並降低誤觸刪除的心理壓力。

**Why this priority**: 龐大表格容易造成看錯行填錯數據。加入懸停反白能強化當前編輯行的視覺聚焦，微型按鈕則改善視覺突兀感。

**Independent Test**:
在路段工項列表中將滑鼠游標移至不同工項列，確認該列立即切換為淡雅高亮底色（`#f8fafc`）；滑鼠移至最左側「×」按鈕時，確認呈現淺紅淡色圓角反白提示。

**Acceptance Scenarios**:
1. **Given** 列表展示多筆工項，  
   **When** 滑鼠移至任一工項列上方時，  
   **Then** 該工項列切換為淺色懸停背景（`#f8fafc`），移開後平順復原。
2. **Given** 最左側的「×」移除按鈕，  
   **When** 平常靜止時呈現淡灰微型圖示（24x24px 圓角），當滑鼠移上去時，  
   **Then** 呈現淡紅底色（`#fee2e2`）與紅色「×」文字，提供清晰的防呆回饋。

---

### User Story 3 - 每日完成數量狀態回饋與無資料引導 (Priority: P3)

作為監工核銷人員，在檢視各工項的每日數量分配時，我希望每日合計具備明確的色彩狀態回饋（如「✓ 已完全分配」為綠色、「超出本月數量」為紅色），且當尚未加入工項時呈現美觀的引導空狀態（Empty State）。

**Why this priority**: 提供直覺的即時試算審核指標，幫助使用者一眼看出分配是否平衡；並在空狀態時引導使用者加入工項。

**Independent Test**:
在每日數量中輸入與本月數量相符的總和，確認右下方顯示綠色「✓ 已完全分配」；輸入超出本月數量的數字，確認顯示紅色「超出」警示；在尚未加入工項的路段確認顯示卡片式空狀態提示。

**Acceptance Scenarios**:
1. **Given** 工項之每日數量總和等於本月數量，  
   **When** 使用者檢視右側下方摘要時，  
   **Then** 顯示綠色高亮標籤「✓ 已完全分配」。
2. **Given** 工項之每日數量總和大於本月數量，  
   **When** 使用者檢視右側下方摘要時，  
   **Then** 顯示紅色高亮警示「超出 [差額]」。
3. **Given** 某路段尚未加入任何工項，  
   **When** 展開該路段時，  
   **Then** 呈現邊框卡片空狀態，提示「目前尚未加入任何工項，請從上方搜尋選取加入」。

---

### Edge Cases

- **極長工項規格名稱**：當工項名稱極長時，應支援文字截斷省略號（`truncate`）並在滑鼠懸停時顯示完整 `title`，不破壞左右兩側版面比例。
- **無施工日設定（整月 31 天）**：當路段未設定施工日而顯示整月 31 天時，右側表格橫向滾動條應保持平滑自訂滾動樣式，不遮擋最後一列。
- **單一施工日模式**：在單一施工日自動同步模式下，右側僅有 1 欄，版面寬度應保持整齊居中，不發生畸形拉伸。

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須重構 `quantity-column-head` 表頭結構，賦予淺灰底色、分欄邊界與圓角骨架，並使表頭標題與下方數據列 100% 垂直對齊。
- **FR-002**: 系統必須將「本月數量」、「單價」、「本月金額」數值欄位設定為靠右對齊（`text-align: right`），並套用等寬數字字型（`font-variant-numeric: tabular-nums`）。
- **FR-003**: 系統必須為工項列（`quantity-item`）加入行間分隔底線與滑鼠懸停（hover）淡雅高亮底色。
- **FR-004**: 系統必須將「×」移除按鈕重構為 24x24px 微型圓角按鈕，平常淡灰圖示，hover 呈現淡紅底色與紅色文字。
- **FR-005**: 系統必須為每日數量分配狀態加入色彩語意標籤（完全分配為綠色、超出為紅色、未分配完為灰字）。
- **FR-006**: 系統必須維持所有樣式變更嚴格隔離於 `quantity-*` 範疇內，100% 不干擾專案其他頁面（`/sites`、`/prior`、`/export` 等）。

---

### Key Entities

- **QuantityBoardPresentation**: 數量看板整體展示層結構，涵蓋表頭、工具列與雙欄對齊網格。
- **ItemRowPresentation**: 工項列展示模型，涵蓋左側帳務數據（代碼、名稱、數量、單價、金額、備註）與右側每日日曆網格。

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 數值欄位（數量、單價、金額）100% 達成靠右等寬對齊，小數點與千分位垂直齊平。
- **SC-002**: 表頭與工項列欄位對齊偏差為 0 像素，徹底消除視覺錯位感。
- **SC-003**: 其他頁面（`/sites`、`/prior`、`/export` 等）CSS 回歸測試影響率為 0%（100% 作用域隔離）。
- **SC-004**: 樣式重構後不產生額外 DOM 重繪負擔，維持 60fps 平滑滾動與輸入回應。

---

## Assumptions

- 專案維持現有 Next.js 16 App Router 與純 CSS（`legacy.css`）設計架構，不引入肥大 CSS 框架。
- 本次改動僅限於視覺呈現與 CSS/JSX 結構微調，不變更任何後端資料持久化與 Server Action 契約。
