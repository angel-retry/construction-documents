# Feature Specification: 整合式可搜尋工項下拉選單 (Searchable Item Combobox)

**Feature Branch**: `002-searchable-item-combobox`  
**Created**: 2026-11-04  
**Status**: Draft  
**Input**: 參考既有 Streamlit 版本的 `st.selectbox(filter_mode="contains")`，將 `/quantities` 頁面中路段加入工項的「搜尋工項文字框」與「原生 select 下拉選單」整合成單一 Combobox 輸入元件：點擊展開下拉清單、輸入關鍵字即時模糊過濾、點選項目後帶入代碼並提交加入。

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 整合式輸入框展開選單與關鍵字即時過濾 (Priority: P1)

作為工程核銷人員，在「每日數量與帳務總覽」（`/quantities`）頁面為各施工路段加入契約工項時，我希望點擊單一輸入框即可直接瀏覽可加入的工項清單，並可直接輸入工項代碼或關鍵字進行即時過濾與點選，避免在分開的搜尋文字框與下拉選單間切換操作。

**Why this priority**: 這是路段工項填報與維護最頻繁的操作環節。將原本繁瑣的兩段式輸入整合成單一 Combobox，能大幅縮短選取動線並降低操作認知負擔。

**Independent Test**:
進入特定標案的 `/quantities` 頁面展開任一路段，點擊「加入工項」輸入框，清單立即展開；輸入關鍵字（例如 `瀝青` 或 `一.`），清單即時過濾僅留相符項目；點擊該項目後按「加入」，該工項成功出現在路段工項表格中。

**Acceptance Scenarios**:
1. **Given** 某施工路段尚有未加入之契約工項，  
   **When** 使用者點擊「加入工項」輸入框時，  
   **Then** 系統展開下拉選項清單，顯示所有尚未加入該路段的可用工項（格式為：`工項代碼｜名稱（單位）`）。
2. **Given** 下拉清單已展開，  
   **When** 使用者在輸入框輸入關鍵字（如代碼 `一.` 或名稱 `瀝青`），  
   **Then** 清單即時進行包含比對（contains filter），僅呈現代碼或名稱符合該字串之項目。
3. **Given** 使用者在清單中點擊特定工項，  
   **When** 點選動作完成，  
   **Then** 輸入框自動帶入該工項之呈現字串，下拉清單自動收合，右側「加入」按鈕轉為可用狀態，且表單隱藏欄位 `code` 正確填入該工項代碼。
4. **Given** 使用者已選取工項，  
   **When** 點擊「加入」按鈕，  
   **Then** 系統將工項加入路段，並向使用者顯示操作成功提示。

---

### User Story 2 - 下拉清單懸浮呈現與操作防呆防跑版 (Priority: P2)

作為填報人員，當我展開工項下拉清單時，我希望清單以懸浮視窗（Overlay）呈現且具備最大高度滾動條，不推擠或破壞下方龐大的日期數量表格；同時支援點擊畫面其他空白處快速關閉，以及在加入成功後自動清空輸入框以便接續選取。

**Why this priority**: 確保畫面整潔與版面穩定，防止展開選單時導致下方數十欄日誌表格劇烈跳動；並在連續新增多筆工項時維持流暢體驗。

**Independent Test**:
展開工項清單時觀察下方數量欄位是否維持不動；點擊外部空白區域確認清單正常收合；成功加入一筆工項後，確認輸入框自動恢復初始狀態。

**Acceptance Scenarios**:
1. **Given** 下拉清單展開，  
   **When** 可用項目較多時，  
   **Then** 清單限制最高高度並提供垂直滾動條，懸浮於既有版面之上，完全不推擠下方工項資料與日期表格。
2. **Given** 下拉清單呈現中，  
   **When** 使用者點擊輸入框以外的空白區域或按下 `Escape` 鍵，  
   **Then** 下拉清單立即自動收合。
3. **Given** 工項成功加入至路段，  
   **When** 頁面狀態更新完畢，  
   **Then** 輸入框自動重置為空白提示狀態（Placeholder），選取狀態重置，「加入」按鈕恢復停用，準備進行下一次選取。

---

### Edge Cases

- **無相符工項**：當輸入的搜尋字串完全比對不到任何可用工項時，清單內應顯示「查無相符工項」提示，而非留白。
- **所有工項皆已加入**：當該標案所有契約工項均已全數加入該路段時，輸入框應顯示「已無可加入工項」並停用選單。
- **僅打字未明確選取**：若使用者僅在輸入框輸入文字但未在下拉選單中明確點選項目，「加入」按鈕維持停用（disabled），防止送出無效代碼。

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須將「關鍵字搜尋」與「工項選取」整合成單一 Combobox 輸入元件，取代 `/quantities` 頁面中原有的分開式搜尋框與原生 `<select>`。
- **FR-002**: 系統必須在使用者點擊或聚焦輸入框時展開浮層清單，僅列出尚未加入該路段之可用合約工項，格式統一為 `工項代碼｜名稱（單位）`。
- **FR-003**: 系統必須在使用者輸入文字時，依工項代碼與名稱即時執行 contains（包含）模糊比對，動態過濾選單項目。
- **FR-004**: 系統必須在使用者點選選單項目後，將該工項代碼自動同步至隱藏欄位 `<input type="hidden" name="code" />`，並啟用「加入」按鈕。
- **FR-005**: 系統必須在未選中有效工項時停用「加入」按鈕，並於加入成功後自動重置輸入狀態。
- **FR-006**: 系統必須支援點擊外部區域（Click outside）或按下 `Escape` 鍵自動收合清單。
- **FR-007**: 下拉清單必須採用絕對定位懸浮樣式，限制最高高度與內部滾動，展開時不得造成下方表格與日期欄位產生位移或跑版。

---

### Key Entities

- **ContractItem (`contract_items`)**: 標案核定合約工項，核心欄位為 `code`（工項代碼）、`name`（工項名稱）、`unit`（計價單位）、`seq`（排序序號）。
- **ItemSelectionState**: 前端元件選取狀態，包含 `isOpen`（下拉是否展開）、`searchTerm`（當前過濾文字）、`selectedCode`（已選定之工項代碼）、`selectedLabel`（選中項呈現標籤）。

---

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者選定工項之操作動線從原先的「點輸入框 → 打字過濾 → 移至下方選單 → 展開點選」簡化為「點輸入框打字 → 點選項目」，步驟縮減 50%。
- **SC-002**: 輸入關鍵字後的清單過濾反應時間低於 50 毫秒，提供毫秒級即時流暢體驗。
- **SC-003**: 下拉清單展開時，下方工項表格與所有橫向日期欄位達成 0 像素位移、0 推擠。
- **SC-004**: 加入工項之表單請求維持 100% 攜帶合規代碼，完全相容現有 `addItem` Server Action。

---

## Assumptions

- 專案維持現有 Next.js 16 App Router 與 React 19 架構，維持原生純 CSS 與 React 實作，不引入第三方大型 UI 庫。
- 工項資料源自標案既有合約工項清單，已由後端過濾排除該路段已加入之工項。
- 本次改動僅專注於 `/quantities` 頁面路段工項加入區之使用者互動與元件封裝，不變更後端 `monthly_items` 資料結構與存取契約。
